# SIRP-1000:2026-DRAFT

## Semantic Integrity, Resilience and Repair Protocol
## 语义完整性、韧性与修复协议

### Status

Author-side pre-standard draft. No standards body approval or certification is claimed.

### 1. Scope

SIRP specifies machine-readable records and governance requirements for analyzing semantic harm mechanisms, preserving protected adverse expression, applying proportionate interventions, and closing correction and repair loops.

### 2. Conformance levels

| Level | Name | Core requirements |
|---|---|---|
| L0 | Semantic act | Explicit content, context, audience, purpose and source scope |
| L1 | Vector analysis | Separate evidence, context, manipulation, addiction, vulnerability, zero-sum and unverifiability dimensions |
| L2 | Plural worlds | Retain benign, negligent, commercial, deceptive and protected-expression hypotheses |
| L3 | Context repair | Produce omitted conditions, vulnerable misreadings, balanced rewrite and reality test |
| L4 | Proportionate intervention | Context before friction; friction before restriction; notice, expiry and appeal |
| L5 | Accountable ecosystem | Human authority, downstream correction, repair, transparent reporting and agent inheritance audit |

### 3. Normative requirements

1. A conforming implementation **MUST NOT** use negative affect alone as a restriction feature.
2. It **MUST NOT** produce a person-level moral, intelligence or positive-energy score.
3. It **MUST** distinguish content truth, context completeness, intent hypotheses and legal responsibility.
4. It **MUST** keep deliberate-deception inference low unless independent fabrication evidence exists.
5. It **MUST** protect criticism, whistleblowing and distress expression by default.
6. It **MUST** expose uncertainty and retained alternative worlds.
7. It **MUST** provide reason codes for every proposed intervention.
8. It **MUST** require a named human process for high-impact adverse action.
9. It **MUST** provide notice, expiry, appeal and correction for de-amplification, monetization suspension or removal.
10. It **MUST NOT** implement secret shadow bans as a conforming action.
11. It **MUST** treat situational vulnerability as scoped, expiring and rights-enhancing.
12. It **MUST** preserve adverse evidence and minority analysis.
13. It **MUST** separate automated proposal authority from external execution authority.
14. It **MUST** support downstream correction after confirmed error.
15. It **SHOULD** expose content provenance and AI-origin declarations where available.
16. It **SHOULD** disable or reduce addictive defaults for minors and vulnerable contexts.
17. It **SHOULD** publish aggregate false-positive, appeal and restoration metrics.

### 4. Reference decision states

```text
ALLOW
PROTECT_NEGATIVE_TRUTH_OR_DISTRESS
ADD_CONTEXT_CARD
ADD_SHARING_FRICTION
REDUCE_RECOMMENDER_AMPLIFICATION_PENDING_REVIEW
PAUSE_MONETIZATION_PENDING_REVIEW
HUMAN_REVIEW_HIGH_RISK
AUTHORIZED_REMOVAL_FOR_ILLEGAL_OR_IMMINENT_HARM
CORRECTION_PROPAGATION_AND_RESTITUTION
```

### 5. External action boundary

The reference implementation has zero automatic external action authority. A platform deployment may implement external actions only through separately authorized connectors and jurisdiction-specific due process.
